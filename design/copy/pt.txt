-- Sistema Wave (Group Wave Enterprise) --
[image] Um quadro de solicitações estilizado, com equipes e tarefas fictícias, no lugar do sistema interno.
[mockup words] Campanhas · Solicitações · Relatórios · Dashboard · Todas as equipes · Esta semana · Nova solicitação · Solicitadas · Em andamento · Em revisão · Concluídas · Criação · Dados · Redação · Mídia · Seg · Ter · Qua · Qui · Sex · Hoje · Feito · Banners, 6 tamanhos · Auditoria de UTMs · Sequência de 3 e-mails · Corte de vídeo, 15 s · Título da landing page · Oferta, versão mobile · Relatório semanal · Pixel no novo domínio · Carrossel, 5 cards · Anúncios, 2ª rodada
O problema: Cada campanha era montada à mão em cada plataforma de anúncios.
O que construí: Uma plataforma interna que publica campanhas na Meta em massa, edita criativos com IA, gera copies, gerencia solicitações entre equipes e mostra dashboards de campanhas e financeiro. O time divide o trabalho por áreas; eu atuo em todas, para que cada parte se encaixe no todo.
Arquitetura:
  App web (Next.js, React) → API (NestJS)
  API (NestJS) → PostgreSQL
  API (NestJS) → API da Meta
Resultado: Mais de 500 campanhas por dia, publicadas por cerca de 100 pessoas.
Stack: Next.js, React, NestJS, TypeScript, PostgreSQL, Meta API, Prometheus, Grafana, Jenkins

-- Campaign BI (Group Wave Enterprise) --
[image] Um gráfico de desempenho semanal com campanhas fictícias e media buyers inventados, no lugar do sistema interno.
[mockup words] Desempenho das campanhas · Mensal · Semanal · S · Receita · Investimento · Por media buyer · campanhas
O problema: O financeiro esperava de 45 minutos a 2 horas por CSV do RedTrack.
O que construí: Desenhei e construí tudo: o n8n publica os dados do RedTrack no RabbitMQ e workers NestJS gravam em paralelo no PostgreSQL, então um registro que falha é refeito e nada se perde. Um app Next.js mostra resultados mensais, semanais e por media buyer.
Arquitetura:
  RedTrack → n8n
  n8n → RabbitMQ
  RabbitMQ → NestJS (workers e API)
  App Next.js (login Google) → NestJS (workers e API)
  NestJS (workers e API) → PostgreSQL
Resultado: Dados atualizados a cada hora, e o Campaign BI hoje roda no Sistema Wave.
Stack: Next.js, NestJS, PostgreSQL, RabbitMQ, n8n, RedTrack
Sistema interno, sem link público

O problema: Gerenciar várias lojas online num só lugar, cada uma com seus próprios produtos, vendas e integrações.
O que construí: Minha própria plataforma multiloja (vitrine, painel administrativo, pagamentos com Stripe), construída em fases com agentes de IA. Arquitetura:
  Vitrine (Next.js) → API (NestJS, monólito modular)
  Painel administrativo (Next.js) → API (NestJS, monólito modular)
  API (NestJS, monólito modular) → PostgreSQL (Prisma)
  API (NestJS, monólito modular) → Stripe (provider de pagamentos)
  API (NestJS, monólito modular) → Resend (provider de e-mail)
  Vitrine (Next.js) → Microsoft Clarity, Pixel da Meta
Resultado: Lançada em outubro de 2026.
Stack: Next.js, NestJS, PostgreSQL, Prisma, Stripe, Resend, Microsoft Clarity, Meta Pixel

-- Hostly (IA Robots Solutions) --
[image] Uma tela de agenda do robô com uma playlist de campanhas fictícia, no lugar do sistema real.
[mockup words] Hoje · Campanha · Música · Boas-vindas · Lobby, trilha A · Oferta semanal · Menu do almoço · Lobby, trilha B · Tocando agora · Campanha, 30 segundos · A seguir · Luz da manhã · Portas abertas · Hora calma · Segundo andar · Check-in tardio
O problema: O app de fábrica não deixava agendar campanhas e não gerava relatório.
O que construí: Escrevi a especificação e desenvolvo o sistema inteiro com agentes de IA: app do robô, painel, API e worker de mídia. O app acessa o RobotOS por uma camada própria, o RobotGateway, então roda sem o robô real e pode migrar para o AgentOS depois.
Arquitetura:
  Painel (Next.js) → API (NestJS)
  App do robô (Kotlin) → API (NestJS) (WebSocket)
  App do robô (Kotlin) → RobotOS no LuckiBot Plus (RobotGateway)
  API (NestJS) → Worker de mídia (FFmpeg) (fila)
  API (NestJS) → PostgreSQL
  API (NestJS) → Telão de LED cadastrado (anúncios)
  Worker de mídia (FFmpeg) → Storage S3
Resultado: Em uso, transmitindo anúncios para o robô e para telões de LED.
Stack: Kotlin, RobotOS, NestJS, Next.js, PostgreSQL, Redis, BullMQ, FFmpeg, Docker
Sistema interno, sem link público

-- BookOwl --
[image alt] A tela inicial do BookOwl: o logo da coruja sobre uma mensagem de boas-vindas.
O problema: A biblioteca de uma igreja não sabia quais livros tinha nem com quem estavam.
O que construí: Construí do começo ao fim em Python e Django, open source, para a secretária da igreja. Cada empréstimo segue seus estados (aguardando retirada, ativo, atrasado, devolvido, cancelado) e atualiza os livros, então a biblioteca sempre sabe o que está na estante.
Arquitetura:
  Telas da biblioteca (navegador) → App Django (Python)
  App Django (Python) → PostgreSQL
  App Django (Python) → Telegram (feedback) (feedback)
Resultado: Em uso na biblioteca da igreja, na versão 1.4.2.
Stack: Python, Django, PostgreSQL, pandas
