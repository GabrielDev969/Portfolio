-- Sistema Wave (Group Wave Enterprise) --
[image] Un tablero de solicitudes estilizado, con equipos y tareas ficticios, en lugar del sistema interno.
[mockup words] Campañas · Solicitudes · Informes · Dashboard · Todos los equipos · Esta semana · Nueva solicitud · Solicitadas · En curso · En revisión · Listas · Creativo · Datos · Redacción · Medios · Lun · Mar · Mié · Jue · Vie · Hoy · Listo · Banners, 6 tamaños · Auditoría de UTM · Secuencia de 3 correos · Corte de video, 15 s · Título de la landing · Oferta, versión móvil · Informe semanal · Píxel del nuevo dominio · Carrusel, 5 imágenes · Anuncios, 2.ª ronda
El problema: Cada campaña se armaba a mano en cada plataforma de anuncios.
Lo que construí: Una plataforma interna que publica campañas en Meta en masa, edita creatividades con IA, genera copies, gestiona solicitudes entre equipos y muestra dashboards de campañas y finanzas. El equipo divide el trabajo por áreas; yo trabajo en todas, para que cada parte encaje en el conjunto.
Arquitectura:
  App web (Next.js, React) → API (NestJS)
  API (NestJS) → PostgreSQL
  API (NestJS) → API de Meta
Resultado: Más de 500 campañas al día, publicadas por unas 100 personas.
Stack: Next.js, React, NestJS, TypeScript, PostgreSQL, Meta API, Prometheus, Grafana, Jenkins
Sistema interno, sin enlace público

-- Campaign BI (Group Wave Enterprise) --
[image] Un gráfico de rendimiento semanal con campañas ficticias y media buyers inventados, en lugar del sistema interno.
[mockup words] Rendimiento de campañas · Mensual · Semanal · S · Ingresos · Inversión · Por media buyer · campañas
El problema: Finanzas esperaba de 45 minutos a 2 horas por CSV de RedTrack.
Lo que construí: Diseñé y construí todo: n8n publica los datos de RedTrack en una cola RabbitMQ y workers NestJS los escriben en paralelo en PostgreSQL, así un registro que falla se reintenta y nada se pierde. Una app Next.js muestra resultados mensuales, semanales y por media buyer.
Arquitectura:
  RedTrack → n8n
  n8n → RabbitMQ
  RabbitMQ → NestJS (workers y API)
  App Next.js (inicio de sesión de Google) → NestJS (workers y API)
  NestJS (workers y API) → PostgreSQL
Resultado: Datos actualizados cada hora, y Campaign BI hoy funciona dentro de Sistema Wave.
Stack: Next.js, NestJS, PostgreSQL, RabbitMQ, n8n, RedTrack
Sistema interno, sin enlace público

-- Zibby --
[image] Una tienda ficticia junto a su panel de administración.
[mockup words] Novedades · Hogar · Cocina · Carrito (2) · Para cada día · Taza de cerámica · Lámpara de mesa · Bolso de lino · Pedidos · Admin · En preparación · Pagado · Despachado · Entregado
El problema: Gestionar varias tiendas online desde un solo lugar, cada una con sus propios productos, ventas e integraciones.
Lo que construí: Mi propia plataforma multitienda (tienda, panel de administración, pagos con Stripe), construida por fases con agentes de IA.   API (NestJS, monolito modular) → Resend (provider de e-mail)
  Tienda (Next.js) → Microsoft Clarity, Píxel de Meta
Resultado: Lanzada en octubre de 2026.
Stack: Next.js, NestJS, PostgreSQL, Prisma, Stripe, Resend, Microsoft Clarity, Meta Pixel

-- Hostly (IA Robots Solutions) --
[image] Una pantalla de programación del robot con una playlist de campañas ficticia, en lugar del sistema real.
[mockup words] Hoy · Campaña · Música · Bienvenida · Lobby, lista A · Oferta semanal · Menú de almuerzo · Lobby, lista B · Reproduciendo · Campaña, 30 segundos · A continuación · Luz de mañana · Puertas abiertas · Hora tranquila · Segundo piso · Check-in tardío
El problema: La app de fábrica no permitía programar campañas ni generaba informes.
Lo que construí: Escribí la especificación y desarrollo todo el sistema con agentes de IA: app del robot, panel, API y worker de contenidos. La app accede a RobotOS por una capa propia, el RobotGateway, así funciona sin el robot real y puede pasar a AgentOS más adelante.
Arquitectura:
  Panel (Next.js) → API (NestJS)
  App del robot (Kotlin) → API (NestJS) (WebSocket)
  App del robot (Kotlin) → RobotOS en LuckiBot Plus (RobotGateway)
  API (NestJS) → Worker de contenidos (FFmpeg) (cola)
  API (NestJS) → PostgreSQL
  API (NestJS) → Pantalla LED registrada (anuncios)
  Worker de contenidos (FFmpeg) → Almacenamiento S3
Resultado: En uso, transmitiendo anuncios al robot y a pantallas LED.
Stack: Kotlin, RobotOS, NestJS, Next.js, PostgreSQL, Redis, BullMQ, FFmpeg, Docker
Sistema interno, sin enlace público

-- BookOwl --

Stack: Python, Django, PostgreSQL, pandas
